# Як ми працюємо

## Пайплайн задачі

```
Issue (To do) → гілка feat/<№>-коротко → коміти → PR "Closes #<№>"
   → CI зелений → рев'ю ментора (≤24 год) → правки → squash merge → issue закривається сам
```

1. Одна задача — одна гілка — один PR. PR більше ~300 рядків — розбити.
2. Коміти англійською, наказовий спосіб: `Add queue selection command`.
3. `main` захищена: лише через PR, CI обов'язковий.
4. Застряг більше ніж на годину — пиши ментору. Не мовчати день.
5. AI-асистенти можна для пояснень, але на рев'ю треба пояснити кожен рядок свого PR.
   Не можеш пояснити — переписуєш.
6. Токен бота й інші секрети — лише в `.env` або змінних середовища, ніколи в git.

## Definition of Done

- [ ] Критерії приймання з issue виконані
- [ ] `mvn verify` проходить локально і в CI
- [ ] Нова логіка покрита тестом
- [ ] Немає закоментованого коду, налагоджувальних `System.out.println`, захардкоджених токенів і шляхів
- [ ] Ментор схвалив PR

## Дошка

Колонки `To do` → `In progress` → `Review` → `Done`. В `In progress` одночасно не більше однієї задачі.
